# Changelog

## 1.0.0 — 2026-10-20

First MVP build of RoomCast.

- Copy link, Open PDF QR Poster, and Copy diagnostics use the same green button as Start. On macOS 26 each section stays its own dark card, with glass inside that card, and the green buttons keep a solid fill and white text. While stopped, the status names the sound source and Change Sound Source opens Settings.
- The main window is titled RoomCast 1.0 Beta Release. The website hero fills the area behind the cards, including when Reduce Transparency is on, and stays visible in the gaps. The level meter is solid green. Settings has a green Save and Close button at the top and the bottom.
- A closed audio pipe returns an error instead of quitting the app. The writer thread already blocked that signal; the rest of the process ignores it as well, so a write from another thread cannot end the broadcast with signal 13.
- The first window says Welcome to RoomCast, shows the app icon, and Choose Sound Source opens Settings. The welcome copy says WiFi needs No Internet, and that sound comes from the mic, a headset, or a mixing desk. Getting Started in the window and the Help menu opens that sheet again without clearing the first-run flag.
- The app name is RoomCast. The bundle id is `channel.roomcast.app`, the program is `RoomCast.app`, and logs and settings use new RoomCast folders. An older `Public EarFi.app` helper is still recognised. Ko-fi, Patreon, and Buy Me a Coffee are green buttons in a section under Health. The listener page copy is in `ListenerPage.en.json`, and the Mac UI strings are in `Localizable.xcstrings`.
- Settings keeps Advanced open in its own card, the same shape as This Mac, with the controls on the left. Section headings on the main window, Settings, and the log use the Start Broadcasting green. The whole Start Broadcasting button accepts a click.
- SwiftUI app. The main window is the broadcast. Settings opens with Cmd-, from the app menu. The poster and the log are their own windows. Credits stays in Settings and About.
- App icon: Walter's yellow loudhailer on purple, masked to a squircle with transparent corners.
- Default quality is Speech: mono, 32 kbps, for about 30 phones on venue Wi-Fi. The encode rate is fixed at 48 kHz in 20 ms frames. There is no sample-rate picker. The app captures with Core Audio and pipes 48 kHz PCM to ffmpeg, because ffmpeg's AVFoundation capture clicks even when the same device is clean in other apps.
- Bundled MediaMTX 1.21.2 and an LGPL FFmpeg 9.0.2 with libopus 1.6.1, built from pinned source.
- Generated `mediamtx.yml`, device selection by Core Audio UID, defaults from the spec, and Reset.
- Start/stop supervision, auto-restart, stall detection, LAN address selection, and file logging. A port that is already in use is named, including the other program, and is not retried. A leftover RoomCast helper can be stopped from the window.
- Invalid saved settings are replaced with defaults instead of crashing Start. A missing audio device is reported and cleared. Reset to defaults writes a full default set back to preferences.
- Start no longer quits while reading ffmpeg output. Progress lines that end with a carriage return, and a chunk that ends on a newline, are split as bytes on one queue. Saved settings were not the cause of that crash.
- Stop, quit, and the next launch end mediamtx and ffmpeg with SIGTERM, then SIGKILL, including the process group. A TCP port that is only closing is not treated as still in use, so Start works again immediately. The UDP ICE port is released with the process.
- Mono sums every input channel in the app before the 48 kHz converter, so a stereo desk is heard when only one side has the voice, at that side's level. The limiter catches a loud sum. Stereo still uses the chosen input and the next one.
- The main window has a Volume slider from -12 dB to +24 dB, default 0 dB. It applies live, without restarting, and a soft limiter keeps a boost from hard-clipping. The level meter next to it shows the boosted level.
- Start and the input picker no longer crash. The meter publishes its level on a timer, and capture finishes the current buffer before the device is closed.
- Capture converts whatever format the device is already using (any rate, sample type, or channel count) to 48 kHz. The app does not change the device's sample rate. A format it cannot open is reported once, instead of retrying. The log records the native format and a peak level every few seconds. Silence for about 5 seconds while live shows a no-signal warning. After a settings change, the button says Apply New Settings Now.
- The listener page title is a Settings field, Broadcast title. Blank stays “RoomCast Broadcast” and follows the app name. The live status line is Live, the elapsed time, and the input device feeding the stream. The no-signal line waits for sustained silence and does not flicker.
- Bluetooth earbuds (for example AirPods) are reopened after macOS switches them to call mode, including a moment with no input channels. The log records the transport and the format after that switch. While they are the mic, their own playback is call quality; a wired or USB mic, or separate wired headphones, keeps the stage clearer. Speech from the mic is still fine for interpreting. Turn Bluetooth off on the phone, and on any other nearby device paired to the earbuds, so the phone does not take them back and interrupt the stream.
- Start no longer crashes when ffmpeg is still running but the stream is not ready yet. The exit status is read only after the process has launched and exited.
- A 48 kHz stereo input (BlackHole, USB PnP) is left on the format the engine already opened. Rewriting that format had stopped the tap, so ffmpeg saw no samples. The log now records tap callbacks, frames in and out, and stdin bytes after 2 seconds, plus each input stream's format. A same-rate, same-channel notification no longer reopens a wired device.
- Capture opens a new HAL IOProc for every Start and every device change, then destroys it on stop, including after "No audio from". The format is that device's own input, read after the device is chosen. A reused engine had kept the default microphone's one channel, and widening it stopped the callback for every later device. The level meter uses the same fresh IOProc. The log says native capture and the device's channel count.
- AirPods are listed once. A second row with the same name and no channels, or the same UID twice, is hidden, and the selection stays on the headset across later device-list refreshes while it drops out during the call-mode switch. Stopping a device that has already disappeared does not call AudioDeviceStop or remove listeners on that id, and a vanished id is not queried. The device list is refreshed on the main thread.
- The app no longer prints the poster. **Open PDF QR Poster** still saves the PDF and opens it. Print that PDF yourself. A page printed from inside the app left the QR blank.
- The main window can open a one-page QR poster as a PDF. Print that PDF yourself. The page is A4, or Letter in the US and Canada. With no Wi-Fi name it shows the broadcast title, the same listener link as the window, and a blank line to write the network in. Settings → Poster stores the Wi-Fi name, security, and hidden-network flag. The password is kept in the Keychain and is left out of the settings file, the log, and Copy diagnostics. When a name is set, the poster leads with a Wi-Fi join code, then the listener code. The PDF is replaced each time it is opened.
- The listener link is `http://<ip>:<port>/`, with no `/live` and no title in the address. The broadcast title is the lock-screen and browser-tab name. The player keeps its own controls, including mute. An older `/live` link redirects to `/`. The title still comes from Settings and does not restart the audio.
- A 48 kHz stereo input reaches ffmpeg again. The preview meter no longer reopens that device while a broadcast is starting, which had left the capture tap with nothing to write. If Start still gets no samples, it stops with “No audio from” the device instead of restarting forever.
- Poster preview, PDF export, and QR copy.
- Organiser manual in `docs/MANUAL.md`: install, Speech, the poster, listener tips, bandwidth for about 30 phones, and a travel-router network. A phone server is described as planned.
- GitHub Actions builds an ad-hoc signed universal app and DMG. Release tags sign with `RELEASE_SIGNING_P12` when that secret exists.

Not yet verified on a Mac with a real audio interface or with phone listeners. See the pull request for what CI covered.
